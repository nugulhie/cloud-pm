# UX·기능 점검 — 2026-10-29

## 판단과 범위

PM의 ‘프로젝트 선택 → PRD 작성 → 작업 전환 → GitHub 연결 → 진행 확인 → 수정·삭제’를 기준으로 코드와 브라우저를 점검했다. 기본 협업 흐름은 구현되어 있다. 장기적인 팀 운영에는 초안 보호·복구, 개인 업무 보기와 일정 관리의 보완이 필요하다. 실제 PM 사용자 인터뷰나 사용성 실험을 수행한 결과는 아니다.

## 디자인 판단

화이트·그린 중심의 색상과 카드 구조는 유지한다. 개선 효과가 큰 부분은 조작 위치, 폼의 글자 크기, 주요 버튼과 삭제 버튼의 구분이다. 프로젝트·PRD·정책 편집창의 제목과 하단 작업 버튼을 고정하고 입력 글자 크기를 맞췄다. 모바일에서는 주요 조작 높이 44px와 입력 글자 16px를 적용했다. PRD 상태 배지가 한 글자씩 줄바꿈되는 현상도 수정했다.

PRD는 열이 많아 모바일에서 상세 대화창과 가로 스크롤에 의존한다. 다음 디자인 작업은 ‘간단 보기/전체 열 보기’와 자주 쓰는 열 고정이 적합하다. 메뉴 수가 많으므로 정보 구조를 PM 업무와 연동·관리로 정리하는 것도 후속 후보다.

## 기능 보완 우선순위

| 우선순위 | 보완할 기능                     | 현재 한계와 필요 이유                                                                                                       |
| -------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| P0       | 작성 중 초안 보존·이탈 보호     | 배경 클릭 보호와 저장 실패 시 입력 유지는 있으나, Escape·닫기·새로고침으로 긴 PRD 입력을 잃을 수 있음                       |
| P0       | 휴지통·복구                     | DB 삭제 표식과 변경 이력은 있으나 사용자가 삭제를 되돌리는 화면·API는 없음. 복구 시 하위 작업·댓글·연결도 함께 검증해야 함  |
| P0       | 비밀번호 분실 복구              | 현재 비밀번호를 알고 있는 상태의 변경만 지원. 본인 확인을 포함한 재설정 경로가 필요                                         |
| P1       | 내 작업·담당자 선택·저장한 보기 | 담당자는 문자열 입력이고 필터는 임시 상태. 서비스 계정과 GitHub 작성자 매핑, 멤버 선택, 내 작업/지연/미할당 바로가기가 필요 |
| P1       | 작업 일정·마일스톤              | 프로젝트 월간 일정과 작업 기한은 제공. 작업 시작일·기간·마일스톤·타임라인과 일정 영향 판단은 부족                           |
| P1       | PRD 변경 영향 확인              | PRD에서 작업·GitHub 이슈를 만들 수 있지만 이후 변경을 자동 전파하지 않음. 차이 보기·변경 알림·선택 반영이 필요              |
| P1       | 정기 PM 요약·기한 알림          | 앱 내 댓글/멘션 알림과 수동 분석은 제공. 정기 브리핑·담당자 변경·마감 알림은 별도 구현 필요                                 |

개발 외 업무의 완료 방식은 **정책 결정이 필요한 항목**이다. 현재 모든 작업의 완료는 YAML의 PR 머지 조건에 따른다. 기획·검토·운영 업무를 같은 보드에 넣으려면 완료 증거와 승인 규칙을 별도로 정해야 한다. 기존 완료 정책은 이번에 변경하지 않았다.

워크스페이스 역할·비개발자 가입·초대·PRD/CSV·정책/용어집·작업 보드·하위 작업·의존성·댓글/멘션·MCP 쓰기는 이미 존재한다. 실제 Claude 연결은 운영망에서 Anthropic 서버의 접속 허용과 사용자 계정 연결 검증이 남아 있다.

## 검증 기준

격리된 데모에서 기존 회귀 검사와 프로젝트 범위·수정 충돌·연쇄 삭제·부분 실패 재시도·분석 응답 순서 검사를 수행한다. 테스트용 프로젝트는 정리하며 운영 계정의 비밀번호나 실제 업무 데이터는 테스트에 사용하지 않는다. API 계약·완료 정책은 유지한다.

## 반영 결과

UX 브라우저 검사 33개, 후속 MCP 자동 검사 127개와 관련 브라우저 검사 4개가 통과했다. 프로젝트·PRD 편집은 390px 모바일에서 포커스·저장 버튼·가로 넘침을 확인했다. 운영 UX 업데이트 후 HTTPS·비인증 차단·모바일 메뉴·프로필 키보드 조작·헬스 검사를 통과했다.

후속 요청으로 업무 MCP 조회·부분 수정 도구 15개를 추가했고, 기본 워크스페이스의 초대 전용 가입을 해제했다. 웹과 MCP의 정확한 범위는 [MCP 안내](mcp.md), 가입 정책은 [사용자 안내](users.md)를 참고한다.
