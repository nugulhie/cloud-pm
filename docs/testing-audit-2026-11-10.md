## 발견하고 수정한 문제

1. MCP 연결·복구 계정 목록이 잘못된 성공 응답을 반환하면 설정 창 전체가 중단됐다. 응답 검증과 오류 안내·재조회를 추가했다. 알림 설정도 같은 실패 경로를 검사하고 보호했다.
2. 정책 선택창을 펼치거나 검색만 해도 표시용 체크박스를 초안 변경으로 판단했다. 제출 이름이 있는 실제 저장 필드만 보관하도록 수정했다.
3. 프로젝트 저장소 검색으로 선택 항목을 숨기면 초안에 그 저장소가 빠질 수 있었다. 전체 선택을 별도 숨김 필드에 보관해 검색과 관계없이 복원한다.
4. 초기 데이터가 준비되기 전 메뉴 클릭이 유실될 수 있었다. 준비 후 활성화하고, 로딩 중 모바일 메뉴의 Esc·초점 복귀도 보완했다.

위 실패 경로를 재현하는 브라우저 검사 6개를 추가했다. 기존 검사는 초안 폐기 확인과 실제 버튼 이름을 사용하도록 갱신했고, 비밀번호 입력은 해당 설정 영역으로 범위를 좁혔다. 검사를 건너뛰거나 실패 허용으로 바꾸지 않았다.

## 운영 상태와 검증 경계

운영 웹·작업자·DB와 백업·상태 관찰 타이머는 정상이며 CloudWatch 경보 6개가 OK였다. 점검 당시 루트 디스크 사용률은 14%, 계정은 6개, 워크스페이스는 2개였다. 동기화 큐의 저장된 작업은 모두 완료 상태였고, 최근 예약 백업은 격리 복원 검증·S3 업로드 성공 상태였다.

운영 점검에서는 실제 업무 데이터를 생성·수정·삭제하지 않았다. 생성·수정·삭제·발행·계정 복구는 합성 계정과 별도 DB, GitHub 모의 서버에서 실행했다. 실제 조직의 이슈·PR 쓰기, 실제 Claude 계정의 최종 연결 동의, 외부 AI 제공자 호출은 이 결과에 포함하지 않는다. 부하 한계나 모든 가능한 입력에 오류가 없다는 의미도 아니다.

## 다시 실행하기

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

화면 검사는 새로운 `E2E_DATA_DIR`과 빈 GitHub·AI 자격 증명으로 `npm run test:e2e`를 실행한다. 운영 DB 주소와 실제 토큰을 사용하지 않는다. 기본 화면 검사는 개발 모드 데모, 인증 검사는 별도 프로덕션 빌드와 `playwright.planning.config.ts`를 사용한다.

```sh
# GitHub 모의는 실제 호스트로 나가는 요청을 프록시에서 처리한다.
PLANNING_HTTP_SIMULATION=true PLANNING_NEXT_DIST_DIR=<별도-빌드-디렉터리> \
  postman simulation run postman/simulations/github-planning.sim.yaml \
  --proxy --proxy-port 7112 --no-history \
  --lift 'env NODE_OPTIONS=--use-env-proxy NO_PROXY=127.0.0.1,localhost,::1 no_proxy=127.0.0.1,localhost,::1 npm run test:e2e:planning'
```

HTTP 모의는 `postman/simulations/`의 기존 구성을 사용한다. 실행할 실제 검증 프로그램은 `tests/github-app-simulation.ts`, `prd-github-simulation.ts`, `prd-multiple-tasks-simulation.ts`, `github-simulation.ts`, `github-webhook-simulation.ts`, `team-planning-simulation.ts`, `github-maintenance-simulation.ts`다. 각 실행은 새 모의 상태로 시작하며, 결과와 프록시의 실제 외부 전달 0건을 함께 확인한다.
