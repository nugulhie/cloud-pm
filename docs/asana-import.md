# Asana 외부 프로젝트 가져오기

프로젝트 현황의 **외부 프로젝트 가져오기**에서 Asana CSV/JSON 파일을 선택한다. 기존 프로젝트를 선택하거나 미리 만들 필요가 없다. **파일 미리보기**에서 생성할 프로젝트 이름·목표·일정과 작업을 확인하고 **프로젝트와 선택 작업 가져오기**를 실행한다. 프로젝트 이름은 확인 후 수정할 수 있다.

GitHub 저장소 연결 없이 프로젝트와 작업을 생성하며, 나중에 프로젝트 관리에서 저장소를 연결한다. 작업이 없는 프로젝트 또는 작업을 모두 선택 해제한 경우 프로젝트만 가져올 수 있다. 파일당 UTF-8·최대 **10MiB·10,000개 작업**을 지원한다. 하위 작업도 개수에 포함한다. 초과 파일은 일부만 저장하지 않고 오류로 안내한다.

미리보기는 페이지당 50개를 표시한다. **정상 항목 전체 선택**은 모든 페이지에 적용되며 페이지를 이동해도 선택을 유지한다. 상위 작업이 다른 페이지에 있어도 함께 선택해야 한다. 가져온 뒤 현황과 태스크 보드는 필요한 만큼 **더 보기**로 펼친다. 전체 개수·상태 집계와 검색은 표시 개수와 관계없이 전체 작업을 기준으로 한다.

[Asana 공식 내보내기 안내](https://help.asana.com/s/article/project-importing-and-exporting?language=en_US) · [작업 필드](https://developers.asana.com/reference/tasks)

## 프로젝트 정보와 식별

- JSON의 `project`, `data.project`, 프로젝트 객체의 `tasks`, 단일 프로젝트 컨테이너를 읽는다. 프로젝트 객체가 없는 작업 배열은 공통 프로젝트 소속에서 이름과 ID를 찾는다.
- CSV의 `Project ID`/`Project GID`, `Project Name`/`Projects`를 사용한다. 정보가 없으면 파일명으로 프로젝트 이름을 제안한다. 여러 명시적 프로젝트 ID를 포함한 파일은 프로젝트별로 분리한다.
- JSON 프로젝트의 `notes`, `start_on`, `due_on`/`due_date`를 목표와 일정으로 반영한다. 없는 필드는 재가져오기 시 유지한다.
- 원본 프로젝트 ID가 있으면 ID로, 없으면 원본 이름 기반 키로 연결한다. 이름만 있는 CSV를 먼저 가져온 뒤 같은 이름·같은 작업 ID가 포함된 JSON을 가져오면 같은 프로젝트로 연결한다.
- 이름이 바뀌거나 동명이어서 자동 판단하기 어려우면 **원본 프로젝트 식별 설정**에서 기존 원본 키를 지정한다. 미리보기에서 기존 프로젝트 연결 여부를 확인한다. 원본 ID가 다른 프로젝트는 이름이 같아도 합치지 않는다.

## 작업과 중복

CSV의 `Task ID`, `Name`은 필수다. `Notes`, `Assignee`/`Assignee Email`, `Due Date`, `Parent Task`, `Completed At`, `Priority`를 인식하며 섹션·태그·기타 열은 설명에 보존한다. JSON은 `gid`/안전한 정수 `id`, `name`, `notes`, `assignee`, `due_on`/`due_at`, `parent`, 중첩 `subtasks`와 우선순위 사용자 필드를 처리한다. ID를 반올림하거나 지수 표기로 바꾼 파일은 사용하지 않는다.

Asana 내보내기의 동명 사용자 지정 열은 `우선순위 [22열]`처럼 원래 열 번호로 구분해 각각 설명에 보존한다. 기본 `Assignee`와 별도의 사용자 지정 `담당자`가 함께 있으면 기본 담당자를 사용하고 별도 담당자는 추가 정보로 남긴다. 작업 ID/이름의 기본 열 자체가 여러 개인 경우에는 해당 열을 명시해 오류로 안내한다.

CSV의 우선순위는 낮음/보통/높음, 하/중/상, low/medium/high 등 명확한 값만 변환한다. `1순위` 같은 별도 등급이나 서로 충돌하는 값은 원문과 경고를 보존하고 기존 우선순위를 유지한다. 새 작업은 보통이다. 빈 CSV 이름은 원본 ID를 포함한 임시 제목을 사용하며 재가져올 때 기존 제목을 바꾸지 않는다.

상위 작업을 함께 선택하거나 이미 가져온 상위 작업을 사용한다. 기본적으로 모호하거나 파일에 없는 상위는 오류로 표시한다. **상위 작업을 연결하지 않고 다시 확인** 또는 **상위 작업 미확인 처리**의 원문 보존 옵션을 명시적으로 선택하면 해당 신규 작업의 상위를 미연결로 가져온다. 기존 상위 연결은 유지하고 원본 상위 이름은 설명/가져오기 기록에 보존한다. 동명이인 상위 중 하나를 임의로 선택하지 않는다. 순환·중복 ID·삭제된 작업의 재생성은 계속 차단한다. 댓글·첨부파일·계정을 Asana에서 동기화하지 않는다. 담당자는 원본 이름/이메일이다.

**기존 유지**는 프로젝트 이름·목표·일정과 기존 작업을 유지하고 새 작업만 추가한다. **갱신**은 파일에 제공한 프로젝트 정보와 작업 필드를 반영한다. 진행 상태·YAML·댓글·GitHub 연결과 생략 필드는 유지한다. Asana 완료 여부는 원본 정보로 설명에 보존하며 새 작업은 `backlog`다. 가져온 뒤 직접 완료하거나 PR 조건으로 자동 완료할 수 있다. 원본에 ID로 명시된 상하위 관계는 태스크 보드의 **계층 보기**와 상세 하위 목록에서 확인한다.

프로젝트 생성·작업·원본 연결을 한 트랜잭션으로 저장해 중간 실패 시 전체 취소한다. 삭제한 프로젝트·작업은 자동 복원하지 않는다. 저장소 미연결 프로젝트는 같은 워크스페이스 멤버가 조회할 수 있다. 저장소를 연결하면 기존 저장소 접근 검사를 적용한다.

## API·MCP

`POST /api/projects/import/asana/preview` 입력은 `{fileName,format:"csv"|"json",content,projectName?,sourceProjectKey?,unresolvedParents?:"error"|"keep_unlinked"}`다. 프로젝트와 작업 미리보기, 경고·오류·개수, `previewHash`를 반환하며 저장하지 않는다. 각 행은 `warnings`, `unresolvedParent`를 포함할 수 있으며 `counts.unresolvedParents`는 상위를 구분할 수 없는 작업 수다. 정책 기본값은 `error`이며 `keep_unlinked` 선택 후 다시 미리 확인한다.

`POST /api/projects/import/asana`는 같은 파일과 `{mode:"skip"|"update",previewHash,ids:[원본작업ID]}`를 받는다. `ids:[]`는 프로젝트만 가져온다. 결과는 `{project,projectCreated,created,updated,skipped}`이며 `project`는 생성/재사용한 프로젝트 ID다. 미리보기 후 프로젝트·작업이 바뀌면 409로 다시 확인한다.

MCP 도구는 `preview_asana_project`, `import_asana_project`다. 대상 프로젝트 ID나 GitHub 토큰이 필요 없으며 쓰기 권한과 재가져올 프로젝트의 접근 권한을 검사한다. 원격 MCP 요청은 기존 100,000바이트 한도이므로 큰 파일은 웹으로 가져온다.

프로젝트/작업 Asana 가져오기 HTTP 경로는 최대 24MiB 요청을 허용하고 파일 콘텐츠는 10MiB 이하로 제한한다. PRD CSV의 기존 1MiB·500행 제한과 다른 API 요청 제한은 유지한다. 기존 `/api/tasks/import/asana`와 `preview_asana_file`/`import_asana_file`은 기존 클라이언트용 작업 추가 계약으로 유지하며 웹의 기본 흐름에는 사용하지 않는다.
