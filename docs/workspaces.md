# 워크스페이스 생성과 전환

## 사용 방법

1. 로그인 후 왼쪽 상단의 워크스페이스 버튼을 누릅니다. 모바일에서는 `W` 또는 이름 첫 글자 버튼입니다.
2. **새 워크스페이스 만들기**에 이름과 설명을 입력하고 생성합니다.
3. 생성자가 소유자가 되며 새 워크스페이스로 전환됩니다. 기존 프로젝트를 자동 복사하지 않으므로 새 프로젝트를 등록합니다.
4. 같은 버튼에서 참여 중인 다른 워크스페이스를 선택할 수 있습니다. 전환 시 프로젝트 필터·선택 항목·분석 결과를 초기화합니다.
5. 왼쪽 아래 개인 프로필의 **워크스페이스 멤버·초대**에서 현재 워크스페이스에 초대합니다. 이미 가입한 사람도 초대 링크에서 수락할 수 있습니다.

## 접근 범위

프로젝트·기능·태스크·연결·완료 평가·내부 변경 이력은 워크스페이스마다 분리합니다. 서로 다른 워크스페이스에서 같은 프로젝트·태스크 식별자를 사용할 수 있습니다. 멤버·소유자·초대는 해당 워크스페이스에만 적용합니다. 새 워크스페이스는 기본적으로 초대로 참여합니다. 관리자가 GitHub 조직 구성원 참여를 허용하면 검증된 구성원도 선택 참여할 수 있습니다. GitHub 조직 관리자라도 해당 공간의 멤버가 아니면 접근할 수 없습니다.

현재 하나의 `GITHUB_ORG` 안에서 여러 워크스페이스를 지원합니다. GitHub 저장소·PR·이슈 수집 캐시는 공유하지만 개인 또는 관리자 공용 GitHub 연결의 저장소 권한을 검사합니다. 워크스페이스 멤버라도 프로젝트의 모든 저장소에 접근할 수 있어야 프로젝트를 볼 수 있습니다. GitHub 계정 없는 사용자도 서비스 계정으로 초대받을 수 있습니다. 한 서비스에서 서로 다른 GitHub 조직 연결은 지원하지 않습니다. 다른 조직은 [운영 튜토리얼](operations-tutorial.md)에 따라 별도 실행 구성·DB·App으로 운영합니다.

기존 계정과 데이터는 **기본 워크스페이스**로 이전합니다. 프로젝트·기능·태스크 ID와 기존 YAML을 바꾸지 않습니다. 이후 다른 워크스페이스에 초대된 신규 사용자는 기본 워크스페이스에 자동 참여하지 않습니다. 기본 워크스페이스의 신규 가입은 기존 초대 전용 설정을 따릅니다.

## 세션과 MCP

브라우저 로그인 세션에 선택한 워크스페이스를 저장합니다. 웹 요청에는 `X-Workspace-Id`를 함께 전달하고 서버가 멤버십을 검사하므로, 전환 중이거나 다른 탭에서 작업하더라도 이전 데이터가 섞이지 않습니다.

개인 MCP 토큰은 발급 당시 워크스페이스에 고정됩니다. 웹 화면 전환으로 Claude의 작업 대상이 바뀌지 않습니다. 다른 워크스페이스를 Claude에서 관리하려면 웹에서 전환한 뒤 새 토큰을 발급합니다. 현재 사용자당 활성 MCP 토큰은 하나이며 재발급하면 이전 토큰이 무효화됩니다.

MCP는 `list_workspaces`, `create_workspace`를 제공합니다. 생성 도구는 현재 연결의 워크스페이스를 전환하지 않습니다. 새 워크스페이스의 토큰을 발급하여 다시 연결하세요. 기존 공용 토큰과 신뢰된 로컬 stdio 연결은 기본 워크스페이스를 사용합니다.

## 운영과 검증

시작 시 DB에 워크스페이스 열·멤버 테이블과 복합 키를 적용합니다. 기존 레코드와 이력의 기본 범위는 `main`입니다. 스키마 변경을 적용할 때 DB를 백업하고 웹·작업자·stdio 프로세스를 모두 새 버전으로 재시작하세요. 개발 중 스키마를 바꿨을 때도 서버를 재시작해야 합니다.

백그라운드 동기화는 공유 GitHub 데이터를 수집하고 각 워크스페이스의 YAML 일치 태스크를 평가합니다. YAML 식별자는 워크스페이스 안에서 해석되므로 같은 설정과 ID를 두 워크스페이스에서 사용하면 각각 평가합니다. 수동 동기화는 현재 워크스페이스만 평가합니다.

자동 테스트는 생성·전환, 비멤버 접근 차단, 멤버·초대·이력 분리, 토큰 범위, 기존 DB 이전, 여러 워크스페이스의 완료 판정과 모바일 화면을 검증합니다. 워크스페이스 삭제·소유권 이전과 여러 활성 MCP 토큰 관리는 후속 범위입니다.

## 역할과 멤버 관리

프로필의 **워크스페이스 멤버·초대**에서 역할을 변경하거나 멤버를 제외합니다.

| 역할      | 허용 범위                                                 |
| --------- | --------------------------------------------------------- |
| 소유자    | 작업 관리, 초대·설정, 관리자 승격·강등, 멤버 제외         |
| 관리자    | 작업 관리, 초대·설정, 멤버·조회 전용 역할 변경과 제외     |
| 멤버      | 프로젝트·기능·태스크·댓글 작성과 수정·삭제, GitHub 동기화 |
| 조회 전용 | 현황·댓글·변경 이력 조회, 본인 알림 읽음 처리             |

소유자의 역할 변경·제외는 지원하지 않습니다. 관리자 등급의 변경·제외는 소유자만 할 수 있습니다. 멤버 제외는 이 공간에만 적용되며 기존 작업·댓글·계정과 다른 워크스페이스는 보존됩니다. 해당 공간의 개인 MCP 토큰, 대상자의 기존 초대와 대상자가 발급한 대기 중 초대는 해제합니다. 제외된 사용자는 프로필에서 다른 공간으로 전환하거나 새 공간을 만들 수 있습니다.

초대 시 멤버·조회 전용 중 역할을 선택하며 기존 초대는 멤버 역할을 유지합니다. 관리자 승격은 가입 후 소유자가 수행합니다. 개인 MCP 토큰의 권한과 현재 워크스페이스 역할 중 더 제한적인 권한을 매 요청에 적용합니다. 조회 전용 사용자는 읽기 토큰만 발급할 수 있고, 기존 쓰기 토큰도 역할 하향 후 조회로 제한됩니다. 이미 처리 중인 요청에는 인증 당시 권한이 적용될 수 있습니다.

GitHub 조직 관리자 역할과 워크스페이스 역할은 분리합니다. 기존 기본 워크스페이스의 조직 관리자는 최초 업데이트 때 관리자 역할로 한 번 이관하며 이후 명시적인 변경을 유지합니다. GitHub 저장소 접근 검사는 모든 역할에 계속 적용합니다. 역할 변경·제외 이력은 서버에 저장합니다.

역할 관리 API는 브라우저 세션으로 `POST /api/auth/members/role` (`userId`, `expectedRole`, `role`)과 `POST /api/auth/members/remove` (`userId`, `expectedRole`)를 호출합니다. 개인 MCP 토큰으로 멤버 관리 API를 사용할 수 없습니다.
