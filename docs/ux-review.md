# UX 개선 — 2026-10-29

추가·수정·삭제의 후속 점검과 기능 보완 우선순위는 [UX·기능 점검](ux-product-audit.md)에 기록한다.

## 확인한 문제와 변경 기준

- 작업 등록: 자동 식별자가 노출되고 제목보다 설정이 먼저 보이며 저장 버튼이 긴 폼 끝에 있다. 제목부터 입력하고 식별자는 자동 처리한다. 상위 작업·의존성·차단 사유·YAML은 추가 설정에 두고 저장 버튼을 고정한다.
- GitHub 활동: 선택하지 않아도 큰 가져오기 패널이 보이며 모바일에서 목록이 첫 화면 아래로 밀린다. 가져오기는 선택 후 표시하고 수집 안내는 펼쳐 읽는다. 프로젝트가 선택된 행 추가는 해당 프로젝트로 바로 연결한다.
- 필터: 다른 메뉴의 검색 조건이 남아 결과가 비어도 원인을 알기 어렵다. 메뉴 이동 시 검색 조건을 초기화하되 프로젝트는 유지한다. 현재 조건 초기화와 결과 없음 안내를 제공한다.
- 연결 대상: 선택한 항목의 저장소를 포함하지 않는 프로젝트도 선택 가능했다. 모든 선택 항목의 저장소를 포함하는 프로젝트만 대상으로 제시한다. 일괄 가져오기 API와 서버 권한 검증은 그대로 사용한다.
- 모바일·키보드: 메뉴 이름을 표시하고, 모달에서 Tab 이동·Escape·포커스 복귀를 지원한다. 입력 모달의 배경 클릭으로 작성 내용이 사라지지 않게 한다.

API 계약·데이터 모델·완료 기준은 바꾸지 않는다. 기존 데이터로 디자인 검토가 어려운 경우 격리된 데모 환경에서 화면 흐름과 회귀 테스트를 확인한다. 운영 계정의 비밀번호를 변경하거나 재설정하지 않는다.

## 검증

- 격리 데모 환경에서 기존 브라우저 검사 27개와 UX 검사 2개 통과. 빈 결과의 초기화 버튼은 빈 결과 영역 안에서 선택하도록 테스트를 보완한 뒤 재검증했다.
- 신규 검사는 작성 중 배경 클릭, 제목 자동 포커스, Tab 순환·Escape·포커스 복귀, 모바일 저장 버튼, 목록 40개씩 표시, 저장소별 연결 대상, 프로젝트 유지와 필터 초기화, 선택·행 단위 연결을 확인한다. 신규 연결 검사는 제어된 API 응답을 사용하며 실제 저장·삭제는 기존 회귀 검사에서 검증한다.
- Prettier 검사 및 TypeScript 검사 통과. 데스크톱 1440px와 모바일 390px 화면을 캡처하여 확인했다.
- `linux/amd64` 운영 이미지 빌드 및 EC2 웹 컨테이너 교체 완료. 교체 전 DB 백업과 이전 이미지를 보관했다.
- 운영 HTTPS에서 모바일 메뉴, 프로필 모달의 Escape·포커스 복귀, 비인증 대시보드 접근 차단을 확인했다. 브라우저 오류는 없었고, Postman 헬스 검사 3개와 ALB 상태가 정상이다. 로그인 후 수정 흐름은 격리 데모에서 검증했으며 운영 사용자의 계정으로 재로그인하지 않았다.
