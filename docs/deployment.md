# 운영 배포와 Claude 연결

## 준비

Docker Compose를 사용할 서버와 해당 서버를 가리키는 DNS 도메인이 필요합니다. Claude의 원격 MCP 요청은 Anthropic 서버에서 오므로 공개 HTTPS 주소를 사용합니다. [Claude 공식 안내](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

```sh
cp deploy/production.env.example deploy/.env.production
chmod 600 deploy/.env.production
```

`DOMAIN`, `GITHUB_ORG`, `POSTGRES_PASSWORD`, `TOKEN_ENCRYPTION_KEY`를 설정합니다. DB 비밀번호와 암호화 키는 각각 `openssl rand -hex 32`로 생성합니다. 이 Compose 구성의 DB 비밀번호는 URL에 넣을 수 있는 hex 값을 사용합니다. 기존 데이터를 이관할 때는 동일한 `TOKEN_ENCRYPTION_KEY`와 검증된 DB 백업을 복원합니다. 키·DB·HTTPS 인증서 볼륨을 백업하세요.

GitHub 수집용 토큰·웹훅 키는 필요에 따라 설정합니다. Claude가 MCP 도구를 호출하는 데에는 `ANTHROPIC_API_KEY`가 필요하지 않습니다. 서버 AI 분석 기능에만 AI 제공자 설정이 필요합니다.

## 실행

```sh
docker compose -p cloud-pm-production --env-file deploy/.env.production -f compose.production.yaml config --quiet
docker compose -p cloud-pm-production --env-file deploy/.env.production -f compose.production.yaml up -d --build
docker compose -p cloud-pm-production --env-file deploy/.env.production -f compose.production.yaml ps
```

웹은 Next.js standalone 이미지로 실행하고 작업자는 별도 이미지에서 같은 PostgreSQL을 사용합니다. PostgreSQL과 앱의 포트는 Docker 내부에 두며 Caddy의 80·443만 공개합니다. DNS·방화벽에서 해당 포트를 서버로 연결하면 Caddy가 인증서를 발급·갱신합니다. [Next.js 배포](https://nextjs.org/docs/app/getting-started/deploying) · [Caddy HTTPS](https://caddyserver.com/docs/automatic-https)

`GET /api/health`는 DB 준비 상태만 `200` 또는 `503`으로 반환합니다. 사용자·조직·DB 접속 정보는 공개하지 않습니다. DB가 준비된 뒤 웹이 정상화되면 작업자가 시작합니다. Caddy의 요청 본문 제한은 128KB, MCP 애플리케이션의 제한은 100,000바이트입니다. 트래픽 제한이 필요하면 운영 게이트웨이에서 별도로 구성합니다.

## 사용자 연결

1. 공개 웹 주소에서 계정을 등록하고 현재 워크스페이스를 선택합니다.
2. 프로필에서 개인 MCP 토큰을 발급합니다. 조회 전용 역할이면 읽기 토큰을 사용합니다.
3. **Claude MCP 연결**의 연결 점검으로 인증·도구 목록을 확인합니다. 입력 토큰은 화면 메모리에만 유지하며 점검은 프로젝트를 생성·수정하지 않습니다.
4. Claude의 Customize → Connectors → Add custom connector에 `https://<DOMAIN>/api/mcp`를 등록합니다. Request headers에 `Authorization: Bearer <개인 MCP 토큰>`을 설정합니다. 현재 방식은 OAuth 로그인 대신 고정 헤더를 사용합니다.
5. 대화에서 커넥터를 활성화하고 “현재 프로젝트 현황을 조회해 줘”로 확인합니다. 실제 Claude 계정에서의 응답을 확인한 뒤 연결 완료로 판단합니다.

프로필의 **현재 토큰의 최근 MCP 요청**에는 시간·클라이언트 이름·요청 종류를 표시합니다. 자체 점검·CLI 요청도 포함하므로 이 기록은 외부 Claude 연결 자체를 보증하지 않습니다. 토큰 회전·폐기 후 이전 토큰의 기록은 현재 연결로 표시하지 않습니다. 팀 공용 커넥터의 고정 자격 증명은 사용자들이 공유합니다. 사용자별 분리가 필요한 연결에는 각자의 개인 토큰을 사용하거나 별도의 OAuth 구성을 추가해야 합니다.

## CLI 점검

`MCP_SERVER_URL`과 `MCP_ACCESS_TOKEN`을 로컬 `.env` 또는 프로세스 환경으로 설정합니다. 토큰은 명령 인수나 URL에 넣지 않습니다.

```sh
npm run mcp:check
```

CLI는 초기화와 도구 목록만 조회하고 서버 이름·도구 수·쓰기 지원 여부를 출력합니다. HTTPS와 로컬 HTTP를 허용하고 리다이렉트는 거부합니다. 기존 `APP_URL`은 기본 주소로 사용할 수 있습니다.

## 검증 범위

자동 테스트는 인증 실패·Origin 제한·본문 제한·토큰 회전·현재 워크스페이스와 접속 기록 격리·헬스 응답을 검증합니다. 로컬 Docker 웹 이미지·MCP SDK·PostgreSQL 작업자 `--once`·Compose·Caddy 설정을 검증합니다. 공개 DNS·인증서 발급·실제 Claude 계정 연결은 대상 서버에서 별도로 확인합니다.

## 기존 EC2·ALB 배포

2026-10-29 배포 대상은 서울 리전 `i-0ea0fe35a37c9d3cd`, 주소는 `https://cloud-pm.soldoc.co.kr`입니다. 기존 ALB의 HTTPS 인증서와 IP 접근 제한을 사용합니다. 기존 peer-agent는 운영 종료했으며 사용자 요청으로 소스·전용 실행환경·서비스 설정·소스 백업을 삭제했습니다. 다른 nginx 관리 사이트·SSH·SSM·CloudWatch는 유지합니다.

EC2는 빌드를 수행하지 않습니다. 로컬에서 `linux/amd64` 웹·작업자 이미지를 빌드해 `/opt/cloud-pm-agent`에 전달하고 다음 구성으로 실행합니다.

```sh
docker compose --env-file .env.production -f compose.ec2.yaml up -d
docker compose --env-file .env.production -f compose.ec2.yaml ps
```

`compose.ec2.yaml`은 PostgreSQL 18·웹·작업자에 메모리와 로그 크기 제한을 적용합니다. 앱 포트는 `127.0.0.1:3000`에만 열고 DB 포트는 공개하지 않습니다. 1GB 인스턴스에는 1GB swap을 사용합니다. 비밀 설정은 서버의 `.env.production`(권한 600)에 보관하며 저장소에 넣지 않습니다. 로컬 DB 이관 시 기존 `TOKEN_ENCRYPTION_KEY`를 그대로 사용합니다.

`deploy/nginx.ec2.conf`는 기존 ALB에서 TLS를 종료하고 앱에 프록시합니다. ALB의 `/health`는 앱의 `/api/health`에 연결합니다. CSV JSON 요청을 위해 본문 3MB를 허용하고, 긴 GitHub 동기화와 MCP 응답을 위해 프록시·ALB idle timeout은 3600초를 사용합니다. 기존 `peers.soldoc.co.kr` 주소는 새 주소로 이동합니다.

배포 검증은 HTTPS 인증서, DB 헬스, 기존 계정 로그인, 프로젝트 조회, 같은 출처에서 저장·삭제, CSV 미리보기 및 MCP 초기화·도구 조회를 포함합니다. 다른 출처의 수정 요청은 계속 거부해야 합니다. 보안 그룹의 IP 허용 목록 밖에서는 접속할 수 없으며, 현재 구성에서 외부 Claude 서버의 접속은 별도 네트워크 허용이 필요합니다.

PM 앱 롤백은 보관한 이전 웹 이미지를 운영 태그로 지정하고 웹 컨테이너를 교체합니다. PostgreSQL 볼륨과 비밀 설정은 유지합니다. 이전 peer-agent의 소스와 서비스 설정은 삭제되어 해당 서비스로 복원하는 절차는 제공하지 않습니다.

- GitHub 원본 1,028건은 유지하며 목록 SQL에서 파일 변경 약 48MB를 제외했습니다. 파일 변경은 상세에서 읽습니다. 검증 후 웹 메모리는 약 74MiB였고 재시작·OOM은 없었습니다.

- 임시 전송용 S3 객체와 버킷은 삭제했습니다. 원본 DB·복원 백업은 보존합니다. 당시 보관한 peering 파일은 후속 정리에서 삭제했습니다. 로컬 앱은 데이터 분산을 막기 위해 중지했습니다.

### 2026-10-29 UX 업데이트

웹 컨테이너에 [UX 개선](ux-review.md)을 반영했습니다. DB·작업자·비밀 설정은 유지하며, 배포 전 DB는 `/var/backups/cloud-pm-agent/pre-ux-20261029.dump`, 이전 웹 이미지는 `cloud-pm-agent:web-before-ux-20261029`로 보관했습니다. 이 업데이트의 앱 롤백은 이전 이미지를 운영 웹 태그로 다시 지정한 뒤 `up -d --no-deps --wait app`으로 교체합니다. DB를 이전 백업으로 덮어쓰지 않습니다.

브라우저 검사 29개, 포맷·타입 검사와 운영 이미지 빌드가 통과했습니다. 운영 HTTPS에서 새 모바일 메뉴·프로필 키보드 동작·비인증 접근 차단·JavaScript 오류 없음을 확인했고, Postman 헬스 검사 3개 및 ALB 대상 상태도 정상입니다. 운영 계정의 비밀번호는 변경하지 않았습니다.

### 2026-10-29 추가·수정·삭제 및 MCP 확장

추가·수정·삭제 UX와 [업무 MCP 도구 15개](mcp.md)를 반영했다. UX 검사 33개, MCP 추가 후 자동 검사 127개·관련 브라우저 검사 4개, 타입·포맷 검사와 운영 이미지 빌드가 통과했다. UX 반영 직전 DB·웹 이미지는 `pre-crud-ux-20261029.dump`, `web-before-crud-ux-20261029`로, MCP 반영 직전은 `pre-mcp-20261029.dump`, `web-before-mcp-20261029`로 보관했다. DB 백업은 `/var/backups/cloud-pm-agent/`에 있다.

요청에 따라 기본 워크스페이스 `main`의 `invite_only`를 false로 변경했다. 변경 전 설정은 `registration-before-20261029.json`으로 보관했다. 서비스 아이디·비밀번호로 초대·GitHub 토큰 없이 가입해 기본 공간에 일반 멤버로 참여한다. 별도 워크스페이스의 설정은 각 공간에 적용한다.

운영 HTTPS에서 임시 계정의 무초대 가입·기본 공간 참여·개인 쓰기 토큰 발급을 확인했다. 해당 토큰으로 MCP 초기화·새 도구 15개 노출·프로젝트 조회 호출이 성공했다. 실제 업무 데이터를 생성·수정·삭제하는 MCP 동작은 격리 자동 검사에서 확인했다. 운영 헬스 Postman 검사 3개와 ALB 상태는 정상이며 웹 재시작·OOM은 없다. 실제 Claude Chat 계정의 외부 연결 확인은 별도다.

검증용 임시 계정·멤버십·세션·MCP 접속 기록을 정리하고 해당 계정이 남아 있지 않음을 확인했다. 임시 전송 S3 객체·버킷과 격리 데모 서버도 정리했다.

### 이전 peer-agent 정리

사용자 요청으로 `/opt/claude-peers`, `/var/lib/claude-peers`, `claude-peers.service`와 기존 소스·nginx 설정 백업을 삭제했다. 컨테이너가 참조하지 않는 미태그 이미지 2개도 삭제했다. PM 운영·롤백 이미지와 DB 백업은 유지했다.

약 200MiB를 확보해 루트 디스크 사용률이 81%에서 78%로 낮아졌다. 여유 공간은 약 1.8GiB이며 PM 웹·작업자·DB는 실행 중이다. 앱/DB 헬스와 nginx 설정 검사를 통과했다.

### 시스템 로그 보관 제한

`deploy/journald.conf`를 호스트의 `/etc/systemd/journald.conf.d/90-cloud-pm-retention.conf`로 설치했다. journal은 최대 128MiB·최대 7일 보관하며 파일당 최대 16MiB, 파일 교체 주기는 최대 1일이다. `SystemKeepFree=1G`로 journal이 사용할 공간에 제한을 추가한다. nginx·감사·SSM 로그의 기존 순환 정책은 유지한다.

`journalctl --sync` 후 journald를 재시작하고 `journalctl --rotate`, `journalctl --vacuum-size=128M --vacuum-time=7d`로 정리했다. journal은 약 805MiB에서 43.7MiB로 줄었고 약 761MiB를 확보했다. 루트 디스크 사용률은 78%에서 69%, 여유 공간은 약 2.5GiB가 됐다. 새 로그 기록·journald 실행·PM 앱과 DB 헬스를 확인했다. 실행 기록과 이전 제한 설정 백업은 `/var/backups/cloud-pm-agent/log-retention/`에 보관한다.

### Asana 파일·PR diff 업데이트

Asana CSV/JSON 가져오기와 PR 파일의 통합 색상 diff를 추가했다. 검증은 자동 검사 135개·브라우저 검사 36개, 격리 데모의 Postman 미리보기 검사 3개와 운영 이미지 빌드를 포함한다. 브라우저 검사는 두 파일 형식의 선택·중복 유지·갱신·상위 관계·모바일과 100KB 초과 미리보기·다른 출처 차단을 확인한다. 실제 Asana 계정/API와 통신하지 않으며 사용자가 내보낸 파일을 처리한다.

업데이트 전 웹 이미지는 `cloud-pm-agent:web-before-asana-diff-20261029`, DB는 `/var/backups/cloud-pm-agent/pre-asana-diff-20261029.dump`로 보관한다. 앱 이미지만 교체하며, 서버의 비밀 설정·DB 볼륨·로그 보관 제한을 유지한다. 파일의 업무 데이터 매핑과 완료 정책은 [Asana 가져오기 안내](asana-import.md)를 따른다.

운영 반영 후 HTTPS·헬스·새 Asana/diff CSS 자산·비인증 가져오기 차단·모바일 너비와 브라우저 오류 없음을 확인했다. 운영 헬스 Postman 검사 3개와 ALB 대상도 정상이다. 실제 파일의 생성·갱신은 격리 환경에서 검증했고 운영 업무 데이터를 테스트로 가져오지 않았다. 배포 후 디스크 여유는 약 2.4GiB이며 웹 재시작·OOM은 없다.

### Asana 외부 프로젝트 가져오기 업데이트

프로젝트 현황에서 Asana 파일로 프로젝트 자체와 선택 작업을 함께 생성한다. 기존 프로젝트·GitHub 연결이 필요 없으며 원본 프로젝트 ID/키로 재가져오기를 식별한다. 새 HTTP 경로와 MCP 도구는 [Asana 가져오기 계약](asana-import.md)에 정리했다. 프로젝트·작업·원본 연결을 원자적으로 저장하며 기존 저장소 기반 프로젝트의 마지막 저장소 제거는 차단한다.
