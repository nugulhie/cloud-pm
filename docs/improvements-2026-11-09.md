# 실사용 개선 안내

## 작성 중인 내용과 삭제 복구

PRD·정책·용어·프로젝트·태스크와 관리 편집창은 입력을 현재 브라우저에 자동 보관한다. 초안은 사용자·워크스페이스·항목별로 분리하며 7일 후 만료한다. 다시 열 때 **초안 복원**으로 확인하고 저장하거나 폐기한다. 다른 브라우저로 동기화하지 않으며 비밀번호·접근 토큰·파일 입력은 보관하지 않는다. 민감한 본문을 작성하는 공유 PC에서는 사용 후 초안을 폐기한다.

작성 중 닫기·Escape에는 보관/폐기 선택이 나온다. 저장에 성공하면 해당 초안을 제거한다. 원본이 바뀐 초안은 안내를 확인하고 최신 내용과 비교한다. 댓글 입력은 문서 초안 대상에서 제외한다.

**휴지통**은 삭제 당시 묶음의 하위 태스크·댓글·연결·검토 기록을 함께 복구한다. 현재 저장소 권한과 참조, 삭제 이후 버전 충돌을 검사하며 실패하면 전체를 취소한다. 먼저 별도로 삭제한 부모 프로젝트가 있다면 부모부터 복구한다. GitHub 원본은 삭제·복구하지 않는다. 복구한 태스크는 버전이 바뀌므로 과거 검수는 다시 확인한다. 기존 삭제 기록도 현재 tombstone과 감사 이력이 일치하는 묶음에 한해 이관한다.

## 정책·PRD 변경 검토

**검토·릴리스 → 변경 검토**에서 변경 전후 내용, 간접 의존 정책의 PRD 및 연결된 태스크를 확인한다. 대상별 검토자·메모·검토 결과를 기록한다. 선택 반영은 사용자가 입력한 내부 태스크 제목·설명만 변경한다. 정책 내용이나 GitHub 원문을 일괄 덮어쓰지 않는다.

원본이 다시 바뀌면 최신 검토를 사용한다. 대상 태스크가 바뀌었으면 새 버전을 확인한다. 많은 대상은 더보기로 확인하며 검토 기록도 페이지로 나누어 읽는다.

## 기획 검수와 배포

태스크의 직접 완료·PR 조건 완료와 별도로 **기획 검수**에서 검토자를 지정해 검수를 요청한다. 지정 검토자 또는 관리자는 근거를 적어 승인·반려한다. 요청 이후 태스크가 수정되면 재검수가 필요하다.

**일정·릴리스**에서 마일스톤 목표일, 릴리스 예정일·환경·작업 목록을 관리한다. 실제 배포 기록은 완료했고 현재 버전이 승인된 태스크에 실제 배포일을 지정해야 한다. 실제 기록은 수정·개별 삭제 대신 후속 기록을 남긴다. 이 기능은 배포 실행기가 아니다. 계획이 참조하는 태스크는 연결을 해제한 뒤 삭제한다.

타임라인은 시작일·기한을 표시한다. 일정 영향 미리보기는 선행 작업 변경으로 늦어지는 후속 작업을 계산하고 선택한 변경만 적용한다. 모든 관련 버전을 다시 검사하며 충돌하면 새 미리보기를 만든다. 계산은 달력 날짜 기준이며 공휴일·개인 공수 최적화는 포함하지 않는다. **리소스 계획**에서 가용 시간을 함께 확인한다.

## 알림과 PM 요약

프로필 **알림**에서 담당자 변경·기한·일일·주간 요약을 설정한다. 선행 작업 완료, 변경 검토 배정, 기획 검수 요청·결과도 개인 알림함에 표시한다. 알림은 접근 가능한 현재 업무만 보여 준다. 일일 요약은 한국 시간 09시 이후, 주간 점검은 월요일에 한 번 생성하며 작업자가 실행 중이어야 한다.

**PM 요약**은 오늘·이번 주의 등록, 완료 전환, 승인과 현재 지연·차단·미할당을 구분한다. 가져올 때 이미 완료였던 항목은 완료 전환과 별도로 집계한다. 메일·Slack 전송은 구성하지 않는다.

## 계정 복구·소유자 양도·MCP

서비스 소유자는 프로필 **보안**에서 현재 비밀번호 또는 최근 GitHub 로그인을 확인한 후 다른 비밀번호 계정의 복구 코드를 발급한다. 코드는 30분·일회용이며 발급자가 대상자에게 직접 전달한다. 로그인 화면의 복구 메뉴에서 새 비밀번호를 설정하면 기존 세션·개인 API 토큰·MCP OAuth 연결을 만료시킨다. GitHub 계정은 GitHub에서 복구한다.

소유자 본인이 분실했다면 서버 운영자가 다음 명령으로 해당 비밀번호 계정의 복구 코드를 발급한다. 실행 전에 대상 아이디를 확인하고 코드를 로그·이슈에 붙이지 않는다.

```sh
docker compose --env-file .env.production -f compose.ec2.yaml exec worker \
  node --import tsx src/operations/issue-recovery.ts \
  --login <서비스-아이디> --confirm-account-recovery
```

워크스페이스 **소유자 양도**는 현재 소유자가 재인증하고 해당 공간의 멤버를 선택한다. 기존 소유자는 관리자로 남는다. 소유자 권한은 워크스페이스별이다.

MCP는 [계정 인증 연결과 도구 안내](mcp.md)를 따른다. 새 검토·검수·일정·요약·휴지통 업무도 웹과 같은 권한·revision을 검사한다. 계정 보안 작업과 서버 백업은 웹 또는 운영 절차를 사용한다.

## 동기화·백업

초기 동기화 이후 웹훅을 기본으로 사용하고, 매시간 누락된 변경분을 보정한다. 원본 확인은 저장소별 최대 20개를 순환 검사하므로 전체 접근 상태 검사는 여러 주기가 걸릴 수 있다. API 한도가 부족하면 대기하며 진행 중인 정기 보정은 중복 생성하지 않는다. 403·404는 삭제로 단정하지 않고 접근 불가로 표시하며 캐시 본문·diff를 비운다. 명확한 삭제 이벤트만 삭제 상태로 표시한다.

작업 큐의 관리자 카드에서 동기화·백업·서버 상태를 확인한다. [백업·복구 운영 안내](backup-operations.md)에 보존·격리 복원·경보 절차가 있다. 브라우저 자동화·공식 MCP SDK·외부 HTTP 모의 검증은 합성 계정과 격리 DB를 사용한다. 실제 Claude 계정 연결 동의는 사용자가 진행한다.

## 검증 기록

2026-11-09 기준 단위 테스트 232개, 인증 브라우저 시나리오 9개, 타입 검사·포맷 검사·프로덕션 빌드가 통과했다. GitHub HTTP 모의는 업무 브라우저 8건과 누락 보정 6건이며 실제 외부 전달은 0건이다. 공식 MCP SDK로 인증 자동 발견·동적 등록·동의·PKCE·읽기/수정·철회를 검증했다. 모바일 일정 화면의 전체 페이지 가로 넘침도 확인했다. 실제 Claude 계정 연결과 실제 조직 이슈 수정은 이 자동 검증에 포함하지 않는다.
