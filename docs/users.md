# 사용자와 프로필별 토큰

## 등록과 로그인

서비스 아이디(영문·숫자·하이픈 3~39자)와 10자 이상의 비밀번호로 가입하거나 GitHub OAuth로 가입·로그인합니다. GitHub 계정이나 개인 토큰 없이 서비스 계정으로도 참여할 수 있습니다. 서비스 가입의 초대 전용 설정이 켜져 있으면 초대 링크가 필요합니다. 새 워크스페이스는 초대로 참여하며, 관리자가 GitHub 조직 구성원 참여를 허용하면 검증된 구성원도 참여할 수 있습니다. 이메일 확인·회사 SAML/OIDC SSO는 제공하지 않습니다.

새 DB의 첫 가입자는 기본 공간 소유자가 됩니다. 기존 DB 이전 시에는 계정을 새로 만들지 않고 기존 소유자를 보존합니다. [최초 소유자·관리자 설정 튜토리얼](operations-tutorial.md#4-완전히-새-db-첫-소유자를-만든다)을 참고하세요.

기존 GitHub 아이디 기반 계정과 API 가입은 호환됩니다. 개인 GitHub 연결을 추가할 때는 `/user`·조직 멤버십·접근 저장소를 검증합니다. 서비스 아이디와 연결된 GitHub 로그인은 별도로 보관합니다. 관리자 역할과 GitHub 조직 역할은 독립적입니다.

## 저장과 접근

- 비밀번호: 무작위 salt와 scrypt 해시.
- GitHub 토큰: 서버 `TOKEN_ENCRYPTION_KEY`로 AES-256-GCM 암호화. UI에는 마지막 4자리만 제공.
- 웹 세션: 무작위 토큰의 SHA-256 해시를 DB에 저장하며 7일 만료. HttpOnly·SameSite=Lax 쿠키, HTTPS에서 Secure.
- 개인 MCP/API 토큰: 무작위 원문은 발급 직후 한 번만 표시하고 해시만 저장. 조회 전용·조회/수정 중 선택.

개인 및 워크스페이스 공용 GitHub 연결의 접근 저장소를 최대 60초 캐시합니다. 만료 후 재검증에 실패하면 저장소 목록을 비우고 데이터 접근을 거부합니다. 프로필 자체는 열 수 있어 토큰을 교체할 수 있습니다. 토큰 교체는 같은 GitHub 계정만 허용합니다.

프로젝트는 포함된 저장소 전체에 접근할 수 있을 때 표시합니다. 부분 프로젝트 집계를 전체 진행률처럼 보이지 않게 하고, 관련 기능·태스크·연결·변경 이력도 같은 범위를 적용합니다. 수동 동기화·이슈 생성은 워크스페이스 공용 연결을 우선 사용하고, 공용 연결이 없으면 개인 토큰을 사용합니다. 조직 백그라운드 수집은 설정한 GitHub App 설치 인증을 사용하고, App이 없으면 서버의 `GITHUB_TOKEN`을 사용합니다. 단순 캐시는 접근 권한을 부여하지 않으며, 관리자 공용 연결은 해당 연결의 저장소를 해당 워크스페이스 멤버에게 명시적으로 공유합니다. 조회 역할은 외부 이슈를 생성할 수 없습니다.

## 설정 변경과 전환

왼쪽 아래 개인 프로필 버튼을 누르면 표시 이름·GitHub 토큰·비밀번호 설정 창이 열립니다. 비밀번호 변경 시 현재 세션 외의 로그인 세션을 만료시킵니다. 개인 MCP 토큰의 재발급·폐기는 기존 원문으로 접근할 수 없게 합니다. 읽기 전용 MCP 토큰으로 프로필·비밀번호·토큰 발급을 변경할 수 없으며 브라우저 로그인이 필요합니다.

사용자가 한 명 이상 등록되면 기존 `APP_READ_TOKEN`·`APP_WRITE_TOKEN`은 기본적으로 거부합니다. 호환 옵션 `ALLOW_LEGACY_ACCESS=true`는 기존 전체 워크스페이스 접근을 허용하므로 사용자별 권한 제한을 우회할 수 있습니다. 운영에서는 설정하지 않습니다. 기존 브라우저·MCP를 개인 로그인/토큰으로 전환하세요.

로컬 stdio MCP는 `MCP_ACCESS_TOKEN` 설정 시 개인 권한을 적용합니다. 미설정 시 로컬 OS 사용자를 신뢰하는 관리 연결입니다. 서버 암호화 키는 DB와 별도로 안전하게 백업하며 임의로 교체하지 않습니다.

## 워크스페이스 멤버와 초대

하나의 GitHub 조직 안에서 여러 워크스페이스를 만들 수 있습니다. 멤버는 개인 연결 또는 관리자 공유 연결로 접근 가능한 저장소의 프로젝트를 볼 수 있습니다. GitHub 계정이 없는 PM도 초대받아 참여할 수 있으며, GitHub 자체의 저장소 멤버로 추가되지는 않습니다. 공유 설정은 다른 워크스페이스에 전파되지 않습니다. [생성과 전환 안내](workspaces.md)를 확인하세요.

개인 프로필 창의 **워크스페이스 멤버·초대**에서 현재 공간의 멤버 목록과 역할을 확인합니다. 기본 워크스페이스는 최초 가입자가, 새 워크스페이스는 생성자가 소유자입니다. 소유자 또는 해당 공간의 관리자가 초대와 멤버를 관리하며 관리자 등급 변경은 소유자만 할 수 있습니다. GitHub 조직 관리자 역할과 워크스페이스 역할은 분리하며 기존 기본 공간의 조직 관리자는 업데이트 시 관리자 역할로 한 번 이관합니다. 새 워크스페이스는 초대받은 멤버만 참여할 수 있습니다.

- 7일 유효한 일회용 초대 링크 발급. 서비스 아이디를 지정하면 해당 계정만 사용할 수 있습니다.
- 대기 중 초대 취소와 가입 완료·만료 상태 확인. 초대 원문은 발급 직후에만 표시하며 DB에는 해시를 저장합니다.
- **초대 링크로만 신규 가입 허용** 설정. 기존 동작을 유지하기 위해 기본값은 꺼짐이며, 켜면 새 계정 등록에 초대가 필요합니다. 기존 멤버 로그인에는 영향이 없습니다.

초대받은 사람은 링크를 열어 서비스 아이디와 새 비밀번호로 가입합니다. 링크에는 URL fragment를 사용하고 화면 로딩 시 주소에서 제거합니다. `APP_URL`은 초대받는 사람이 접근 가능한 HTTPS 주소로 설정하세요. `127.0.0.1`·`localhost`는 서버가 실행되는 Mac에서만 접속할 수 있습니다. 이메일·메신저 전송은 자동으로 수행하지 않습니다.

## 현재 한계

비밀번호 분실 복구, 계정 삭제·차단 콘솔, 소유자 양도 화면, 회사 SSO·서비스 자체 다중 인증과 한 서비스의 여러 조직 연결은 후속 범위입니다. GitHub OAuth와 기존 계정 연결은 지원하며 조직 멤버십을 검증합니다. 로컬 자동 테스트는 GitHub 응답을 모의하고 실제 조직·토큰 검증은 별도로 수행합니다. [계정 연결·담당자 매칭](team-planning.md)을 참고하세요.

## 운영 가입 설정 — 2026-10-29

운영 기본 워크스페이스 `main`의 초대 전용 가입을 해제했다. 서비스 아이디·비밀번호로 가입하면 기본 워크스페이스의 일반 멤버로 참여한다. 가입에는 GitHub 계정·토큰·관리자 승인이 필요 없다. GitHub 연결은 별도로 설정한다.

별도 워크스페이스의 초대 정책과 기존 데이터의 역할·저장소 접근 범위는 각 공간에 적용된다. 계정 생성이 관리자 권한을 부여하지는 않는다. 기본 공간의 가입 정책은 소유자·관리자가 프로필의 워크스페이스 설정에서 관리한다.
