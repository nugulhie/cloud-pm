# 통합 작업과 GitHub 활동

기능과 태스크는 사용자 화면에서 같은 작업이다. 프로젝트를 고른 뒤 제목으로 바로 등록하며 별도의 기능 등록·선택은 요구하지 않는다. 작업 유형, 담당자, 일정, 설명, 하위 작업, 의존성 및 YAML 완료 조건은 유지한다.

## 하위 태스크와 직접 완료

태스크 보드의 **계층 보기**에서 부모를 펼쳐 하위·손자 작업을 확인하고 각 행의 **＋ 하위**로 추가한다. 상세 창에는 상위 이동, 하위 목록, 완료 개수, 하위 추가가 있다. **상위 태스크** 선택은 기본 입력에 표시하며 자신과 하위 작업은 상위 후보에서 제외한다. 검색·상태 필터에서 부모가 빠져도 일치하는 하위는 숨기지 않고 상위 문맥을 표시한다. 대량 하위는 50개씩 펼친다.

`POST /api/tasks`의 `data.parentId` 또는 MCP `create_task`의 `parentId`로 같은 관계를 만든다. `list_tasks`에 `parentId`를 전달하면 직계 하위를 조회하며 각 하위에도 같은 방식으로 작업을 추가한다. Asana JSON의 ID가 있는 중첩 관계와 CSV의 명확한 관계도 이 화면에 반영한다. 이름만 있어 모호한 관계는 [가져오기 정책](asana-import.md)을 따른다.

PR 없이 `status:"done"`으로 완료하고 다른 상태로 재개방할 수 있다. 웹의 상태 메뉴·드래그·계층/하위 목록 체크박스와 MCP 부분 수정이 같은 권한·revision 검사를 사용한다. `POST /api/manage/update`의 `patch:{status:"done"}`로 최대 100개를 일괄 변경한다. 부모와 하위 상태는 독립적으로 관리하며 자동으로 연쇄 완료하지 않는다. PR 조건에 따른 자동 완료도 유지한다.

## 호환 API

- `POST /api/tasks`: 기존 입력을 유지하고 `data.feature`는 생략 가능하다. 기존 작업 수정은 기존 연결을 보존한다. 신규 하위 작업은 상위 작업의 호환 연결을 사용하며 신규 최상위 작업은 서버가 내부 연결을 마련한다. 내부 feature 식별자는 기존 YAML/MCP 호환을 위해 저장하지만 사용자 입력 단계에서는 숨긴다.
- `POST /api/items/import`: `project`, `items`로 등록 가능하다. `feature`가 없는 요청은 프로젝트 전체의 기존 승인 연결을 기준으로 중복을 막는다. 명시적인 기존 feature 입력도 지원한다.
- `POST /api/work-items/migrate`: 쓰기 권한이 있는 프로젝트의 태스크 없는 기존 기능만 작업으로 전환한다. 원본 기능·인수 기준은 보존하고 반복 호출은 중복 생성하지 않는다. 접근할 수 없는 프로젝트는 건드리지 않는다.
- 기존 `/api/features`와 명시적 feature 입력은 호환 용도로 유지한다. 기존 작업 ID, 완료 조건, PRD 연결, 댓글, 의존성은 변경하지 않는다.

## GitHub 활동

화면의 전체/PR만/이슈만 필터는 기존 상태·저장소·작성자·검색·닫힌 항목 숨김 필터와 함께 적용한다. 라벨은 이름과 색상, 담당자는 assignees, 리뷰 요청은 개인 reviewers와 팀 reviewerTeams로 표시한다. 이슈에는 리뷰어가 적용되지 않는다. 구버전 캐시에 라벨이 없으면 미수집으로 표시하며 다음 GitHub 수집 시 갱신한다. 리뷰 요청 대상은 이미 리뷰를 완료한 사람 전체 목록을 뜻하지 않는다.

프로젝트 필터는 저장소 이름의 대소문자와 관계없이 연결 저장소만 표시하고, 프로젝트 변경 시 개별 저장소·선택 항목을 초기화한다. `POST /api/sync`에 `project`를 전달하면 서버가 해당 프로젝트의 저장소와 접근 권한을 검증하여 그 저장소만 수집한다. 프로젝트를 생략하면 기존 전체 동기화를 유지한다.

## 대시보드 데이터 크기

`GET /api/dashboard`와 프로젝트 현황 MCP 응답은 GitHub 파일·patch를 포함하지 않는 목록 요약을 반환한다. 파일 변경은 `GET /api/github/item?id=owner%2Frepo%231`에서 단일 항목으로 읽는다. 인증과 저장소 접근 권한은 동일하게 적용하며 없는 항목과 접근할 수 없는 항목 모두 404를 반환한다. MCP `get_pull_request_changes`는 기존처럼 전체 파일 변경을 반환한다. UI는 상세를 여는 동안 로딩·실패·재시도를 표시하며 목록의 원본 데이터나 DB 파일 변경을 삭제하지 않는다.

## PR 파일 변경 표시

GitHub 활동의 PR 상세에서 파일을 펼치면 통합 diff를 표시한다. 추가 줄은 초록색, 삭제 줄은 빨간색, 변경 구간은 파란색이며 이전·이후 줄 번호와 `+`/`−` 표시를 함께 제공한다. 이름 변경은 이전 경로와 새 경로를 표시한다. 가로 스크롤은 변경 내용 안에서 처리한다.

바이너리·생략된 patch는 원본 확인 링크로 안내하며, 한 파일의 화면 표시는 최대 10,000줄이다. 파일을 펼칠 때만 diff를 해석한다. 변경 내용은 텍스트로 렌더링하고 HTML을 실행하지 않는다. API·MCP의 원본 파일·patch 데이터는 바꾸지 않는다.

## Asana 파일

프로젝트 현황의 **외부 프로젝트 가져오기**로 Asana CSV·JSON에서 프로젝트 자체와 선택 작업을 함께 생성하거나 갱신한다. 기존 프로젝트나 GitHub 저장소 연결이 없어도 시작할 수 있다. [형식·중복·완료 정책·API/MCP 계약](asana-import.md)을 참고한다.
