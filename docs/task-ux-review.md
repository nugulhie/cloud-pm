# 태스크 UX·디자인 점검 — 2026-10-30

UX 검토와 제품 디자인 검토를 병렬로 진행하고, 구현 뒤 화면을 다시 검토했다. 검토 대상은 태스크 보드·목록·계층, 상세, 모바일 및 대량 Asana 작업이다.

## 문제와 반영

- 첫 작업까지 너무 많은 조작부가 쌓였다. 태스크 화면의 주요 행동을 추가 하나로 줄이고 프로젝트·검색을 앞에, 담당자·상태·유형·선행 대기는 접는 필터에 모았다. 성공 알림도 하나로 합쳤다.
- 평면 보드에서 부모·자식이 섞였다. 접고 펼치는 계층 목록을 기본값으로 삼고, 한 패널의 연속된 행으로 제목·상태·담당자·기한을 정렬했다. 보드와 평면 목록도 유지한다.
- 긴 내부 ID가 제목보다 먼저 나왔다. 제목을 앞에 두고 ID는 상세 추가 설정에 남겼다. 전체 프로젝트에서는 프로젝트명을 표시한다. 차단 사유·선행 대기·기한 초과를 조건에 맞게 표시하고 상태 글씨 대비를 높였다.
- 필터에 따라 하위 완료 개수가 달라졌다. 관계와 완료 집계는 전체 작업 인덱스로 계산하고 표시 행만 필터링한다. 숨겨진 하위 개수를 안내하고 깊은 계층은 실제 단계를 표시한다.
- 상세에서 하위와 YAML이 현재 작업보다 앞섰다. 기본 정보 → 하위 → 추가 설정 순서로 바꾸고 고급 설정·GitHub 연결을 접었다. 접힌 입력도 저장 시 유지한다. 수정 중 하위 이동·추가는 입력을 버리지 않고 저장 안내로 보류한다.
- 보드는 한 방향의 상태 흐름으로 정리하고 가로 스크롤을 보드 내부에 한정했다. 키보드·모바일에서는 같은 상태 선택기로 변경한다.

## 검증

로그인 화면을 모사한 격리 데모의 390px 화면에서 첫 작업 위치는 기존 약 830~880px에서 303px로 줄었다. 부모·하위 5개를 사용한 측정이며 실제 위치는 알림·제목·필터에 따라 달라진다. 390·768·1024·1440px의 페이지 가로 넘침, 단일 추가 버튼, 필터 초기화, 전체 관계 집계, 상태 변경, 입력 보존, 접힌 필드 저장, 조회 권한을 확인했다.

단위 검사 149개와 전체 브라우저 검사 42개, 타입·포맷 검사 및 운영 이미지 빌드를 통과했다. 기한은 한국 날짜 기준으로 표시·집계하며 한국 자정 경계와 완료·취소 제외를 단위 검사한다. 데이터 모델·완료 정책·프로젝트 권한은 유지한다.
