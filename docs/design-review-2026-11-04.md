# 구현 화면 디자인 점검 — 2026-11-04

## 판단

화이트·그린 색상, 카드, 상태 색상은 기본 방향이 일관되어 있다. 가장 먼저 개선할 부분은 PM이 프로젝트 상태와 다음 행동을 찾는 데 걸리는 시간이다. 프로젝트 요약을 위로 올리고, 화면별 대표 버튼과 PRD의 기본 열을 정리하는 것이 우선이다.

## 확인 범위

- 현재 로컬 소스의 프로젝트 현황, 태스크 계층·보드·상세, GitHub 활동·PR 상세, PRD, 정책, 용어집, 캘린더, 항목 관리, 프로필 설정을 확인했다.
- 1440×1000, 1024×768, 390×844 화면에서 19개 상태를 캡처했다. 모든 화면·기능의 회귀 검사를 뜻하지는 않는다.
- 격리된 로컬 데모를 사용했다. 로그인 표시·PRD·정책·일정은 브라우저 응답에서만 예시 데이터를 넣었다. 운영 계정·실제 업무 데이터를 사용하거나 변경하지 않았다.
- 브라우저 예외는 없었고, 캡처한 상태의 페이지 전체 가로 넘침은 없었다. PRD·보드의 내부 가로 스크롤은 별도로 평가했다. 실제 PM 사용자 인터뷰는 수행하지 않았다.

## 유지할 부분

- 태스크 계층 보기는 제목·상태·담당자·기한을 비교하기 쉽다. 모바일 첫 태스크도 y=303px로 빠르게 나타났다.
- 진행·리뷰·완료 상태는 색상과 문구를 함께 사용한다.
- GitHub 활동의 연결 프로젝트 표시와 PR 상세의 추가·삭제 diff 색상은 명확하다.
- 설정의 프로필·GitHub·MCP/API·워크스페이스·보안 탭은 정보 구분이 적절하다.
- 태스크 편집창의 하단 저장·취소·삭제 버튼은 모바일에서도 접근할 수 있었다.

캘린더는 현재 프로젝트 기간만 표시한다. 태스크 마감과 선행 작업의 일정 영향을 확인하는 용도로 확장하려면 별도 설계가 필요하다.

## 구현 순서와 확인 기준

1. 프로젝트 현황과 화면별 대표 버튼을 정리한다. 프로젝트 수가 늘어도 첫 화면에서 프로젝트 요약을 확인할 수 있어야 한다.
2. PRD의 간단 보기와 상세를 분리한다. 가로 스크롤 없이 상태·담당자·연결 태스크를 확인할 수 있어야 한다.
3. 태스크 조회 상세와 수정 동작을 정리한다. 목록 문맥을 유지하며 본문과 연결을 읽을 수 있어야 한다.
4. 메뉴·글자·간격·버튼·아이콘을 공통 기준으로 맞춘다. 노트북과 모바일에서 주요 조작이 가려지지 않아야 한다.

## 개선 반영

후속 구현에서 프로젝트 요약을 상단으로 옮기고 완료율·기간·담당자·차단 수를 표시했다. 취소한 작업은 완료율에서 제외한다. 태스크 미리보기는 6개로 제한하고 전체 목록은 보드로 연결한다.

PRD는 핵심 열만 표시하는 간단 보기를 기본으로 제공한다. 전체 열 보기에서는 데스크톱 식별 열을 고정하고, 모바일 간단 보기는 각 항목 안에서 상태·담당자·태스크 연결을 보여 준다. 일괄 작업 버튼은 항목을 선택하면 나타난다.

기존 태스크는 Markdown 조회용 측면 패널로 열고, 상태를 바로 변경하거나 태스크 수정으로 전환할 수 있다. 하위 작업·의존관계·댓글·GitHub 연결 기능은 유지한다. 메뉴는 업무·문서·활동·관리로 묶고 모바일에서는 접는다. 비어 있는 취소 열은 선택적으로 표시한다.

동일한 화면 크기에서 프로젝트 목록의 시작 위치가 데스크톱 약 1432px에서 317px, 모바일은 2793px에서 509px로 이동했다. 80개 태스크 예시도 프로젝트 목록이 317px부터 나타난다. 개선 후 캡처와 측정값은 `.data/design-update-20261104/`에 보관한다.

## 검증 결과

자동 검사 173개와 브라우저 검사 61개를 확인했다. 메뉴·조회 동선과 상세 응답 모사를 현재 화면에 맞게 갱신하고, 모바일 메뉴 안의 워크스페이스 창과 메뉴가 Esc를 함께 처리하지 않도록 별도 검사를 추가했다. 프로젝트 요약·PRD의 1024/768/390px 표시·조회 후 수정 버전·모바일 메뉴와 워크스페이스 전환도 확인했다. 타입·포맷 검사와 linux/amd64 운영 이미지 빌드를 통과했다.
